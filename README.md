# 五子棋 - 人机对弈 (Qt 6.2.4)

## 功能说明

- **棋盘**：标准 15×15 五子棋棋盘
- **随机分配**：每次开局随机决定玩家执黑或执白，AI 自动补位
- **AI 算法**：启发式评分 + Negamax + Alpha-Beta 剪枝 + 攻防结合策略
- **难度选择**：
  - **普通模式**：静态评估 + 贪心策略，响应极快，适合休闲
  - **困难模式**：Negamax + Alpha-Beta 剪枝 + 历史启发 + 一步杀检测，攻防严密
- **悔棋**：可撤销玩家和 AI 各一步
- **视觉**：渐变棋子、最后落子标记、木色棋盘、星位标记

## 使用

1. 启动后点击「新游戏」
2. 选择难度（普通 / 困难）
3. 系统随机分配黑白棋（黑棋先手）
4. 在棋盘交叉点点击落子
5. 支持悔棋（撤销双方各一步）

## 一、算法层面：进攻与防守的权重平衡

### 1. 普通模式（NORMAL）：静态贪心

**核心公式**：

```cpp
int attackScore = evaluatePoint(pt, m_aiColor);     // AI 落这点的进攻分
int defendScore = evaluatePoint(pt, m_enemyColor);  // 对手落这点的威胁分
int totalScore = attackScore * 12 + defendScore * 10;
```

| 项目 | 权重 | 含义 |
|------|------|------|
| 进攻 | ×12 | 自己落子的棋型威胁值 |
| 防守 | ×10 | 对手在此落子的威胁值 |
| 攻防比 | **1.2 : 1** | 进攻略重于防守 |

**设计哲学**：

- 不做搜索，只看"当前这一步"的即时价值
- 进攻权重稍高（12 vs 10），让 AI 倾向于主动进攻而非纯龟缩
- 同一套 `evaluatePoint` 评分体系，只是 `color` 参数不同——本质是比较"我进攻的收益" vs "对手在这里进攻的威胁"

**局限性**：

- 没有组合棋型概念（双活三、四三杀），只看单点
- 不搜索后续变化，可能忽略"分数低但有后续杀招"的点
- 权重固定，不会根据局面动态调整

---

### 2. 困难模式（HARD）：Negamax + 多层攻防平衡

困难模式的平衡是**分层嵌套**实现的，每一层承担不同的攻防职责：

#### 第一层：一步杀检测（绝对优先级）

```cpp
// 根节点最先执行
if (hasWinningMove(m_aiColor, winningMove))  return winningMove;    // 自己能赢 → 直接赢
if (hasWinningMove(m_enemyColor, enemyMove)) return enemyMove;      // 对手能赢 → 直接堵
```

> 任何权重计算都比不上"下一步就赢/就死"，这一层超越所有评分体系。

#### 第二层：走法排序中的攻防兼顾

```cpp
int s = evaluatePoint(pt, color)                  // 进攻分 ×1.0
      + evaluatePoint(pt, opponent) * 0.9         // 防守分 ×0.9
      + m_historyTable[pt] * 1000;                // 历史启发加分
```

| 项目 | 权重 | 说明 |
|------|------|------|
| 进攻 | ×1.0 | 当前走棋者在此点的棋型威胁 |
| 防守 | ×0.9 | 对手在此点的威胁（略低） |
| 历史启发 | ×depth² | 搜索中产生好结果的点优先尝试 |

**注意**：`color` 是参数化的——AI 回合时进攻分是 AI 的、防守分是对手的；玩家回合时自动反转。**每一层搜索都同时考虑攻防**。

#### 第三层：叶子节点评估（防守兜底）

```cpp
return (color == m_aiColor)
    ? (myTotal - enemyTotal * 1.1)    // AI 视角
    : (enemyTotal * 1.1 - myTotal);   // 对手视角（Negamax 自动取负）
```

| 项目 | 权重 | 说明 |
|------|------|------|
| 己方得分 | ×1.0 | 己方棋型总分 |
| 对方得分 | ×1.1 | 对方棋型总分（防守略重） |

**为什么叶子偏防守？** 搜索深度有限（2~5 层），AI 看不到终局杀招，但能感受到"对手威胁在积累"。给防守更高权重，让 AI 在不确定时优先消除隐患。

#### 第四层：终局剪枝（胜负判定）

```cpp
if (consecutive >= 5) {
    return (lastColor == color) 
        ? (1000000 - (10 - depth) * 1000)   // 自己赢：越浅越好
        : (-1000000 + (10 - depth) * 1000); // 对手赢：越深越晚输越好
}
```

成五直接返回极值，攻防在此统一为胜负判定，权重失效。`depth` 惩罚项确保 AI 选择"最快赢/最慢输"的路线。

#### 第五层：禁手过滤（黑棋专属）

```cpp
if (color == BLACK && color == m_aiColor) {
    // 生成走法时直接跳过禁手点
    if (!isForbiddenMove(pt.x(), pt.y(), BLACK)) filtered.append(pt);
}
```

AI 执黑时，三三禁手、四四禁手、长连的点直接排除，不会出现在候选列表中。

### 3. 两种模式对比总结

| 维度 | 普通模式 | 困难模式 |
|------|----------|----------|
| 平衡方式 | 单点加权求和（12:10） | 五层嵌套（一步杀 → 排序 → 评估 → 终局 → 禁手） |
| 搜索深度 | 0（只看当前） | 动态 2~5 层 Negamax |
| 防守触发 | 被动响应（分数够高才堵） | 主动预判（搜索树自然发现威胁） |
| 组合棋型 | 无法识别 | 通过搜索发现双活三、四三等杀型 |
| 禁手处理 | 无 | 走法生成时直接排除 |
| 响应速度 | <5ms | 50~500ms（经优化后） |

---

### 4. 攻防哲学一句话总结

> **普通模式靠"人工调权重"硬平衡，困难模式靠"搜索深度 + 轻量权重引导"让 AI 自己学会攻防转换。**

```
┌──────────────────────────────────────────────────────────────────┐
│                     攻防权重设计哲学                                │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  普通模式：进攻12 : 防守10                                        │
│           → "我想赢" 略重于 "我怕输"                               │
│           → 适合初学者，AI 积极进攻，偶尔漏防                       │
│                                                                  │
│  困难模式：五层嵌套                                                │
│  ├─ 一步杀：优先级最高，超越所有权重                                │
│  ├─ 走法排序：进攻1.0 : 防守0.9 → 微偏进攻（搜索会修正）            │
│  ├─ 叶子评估：进攻1.0 : 防守1.1 → 微偏防守（兜底保护）             │
│  ├─ 终局剪枝：成五 = 极值 → 绝对胜负                               │
│  └─ 禁手过滤：非法点直接排除                                       │
│                                                                  │
│  核心思想：用搜索深度弥补静态权重的不足                              │
│  "不靠调参平衡攻防，靠搜索让 AI 自己发现威胁"                       │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

## 二、棋型层面：定义、判别与评分

### 核心判别函数：`evaluateLine`

```cpp
int evaluateLine(int r, int c, int dr, int dc, Stone color)
```

**扫描逻辑**：从 `(r,c)` 出发，沿方向 `(dr,dc)` 向前后各扫描最多 4 步：

```
        backward            forward
                 ←←←← ● →→→→
                      (r,c)
```

统计四个变量：

| 变量 | 含义 |
|------|------|
| `forwardCount` | 前方连续同色棋子数 |
| `backwardCount` | 后方连续同色棋子数 |
| `forwardOpen` | 前方第一格是空位（未被堵死） |
| `backwardOpen` | 后方第一格是空位（未被堵死） |

```cpp
totalCount = 1 + forwardCount + backwardCount;
bothOpen   = forwardOpen && backwardOpen;   // 两端都空
oneOpen    = forwardOpen || backwardOpen;   // 至少一端空
```

|------|--------|----------|------|------|----------|
| **五连** | ≥5 | 任意 | `● ● ● ● ●` | 1,000,000 | 胜负已定 |
| **活四** | 4 | 两端空 | `○ ● ● ● ● ○` | 100,000 | ⭐⭐⭐⭐⭐ 必胜 |
| **冲四/眠四** | 4 | 一端空 | `# ● ● ● ● ○` | 10,000 | ⭐⭐⭐⭐⭐ 必须应 |
| **死四** | 4 | 两端堵 | `# ● ● ● ● #` | 0 | 无威胁 |
| **活三** | 3 | 两端空 | `○ ● ● ● ○` | 5,000 | ⭐⭐⭐⭐ 核心进攻 |
| **眠三** | 3 | 一端空 | `# ● ● ● ○` | 500 | ⭐⭐⭐ 可发展冲四 |

| **眠二** | 2 | 一端空 | `# ● ● ○` | 50 | ⭐ 低价值 |

### 各棋型详细判别与棋理

#### 活二（Live Two）

```cpp
totalCount == 2 && bothOpen == true
```

```
○ ● ● ○
```

下一步可以发展成活三，是进攻的种子。评分 200。

#### 眠二（Sleep Two）

```cpp
totalCount == 2 && oneOpen == true && bothOpen == false
```

```
# ● ● ○     或     ○ ● ● #
```

需要再走一步才能变成眠三，进攻价值低。评分 50。

#### 活三（Live Three）⭐ 核心棋型

```cpp
totalCount == 3 && bothOpen == true
```

```
○ ● ● ● ○
```

下一步可以走成活四（两端各一个冲四点），对手**必须防守**。是五子棋中最核心的进攻形态，也是"先手"的来源。评分 5,000。

#### 眠三（Sleep Three）

```cpp
totalCount == 3 && oneOpen == true && bothOpen == false
```

```
# ● ● ● ○     或     ○ ● ● ● #
```

只能发展成一个冲四，威胁有限。评分 500。

#### 活四（Live Four）⭐ 必胜型

```cpp
totalCount == 4 && bothOpen == true
```

```
○ ● ● ● ● ○
```

两端都能成五，对手只能堵一头，**必胜**。评分 100,000。

#### 冲四 / 眠四（Sleep Four）

```cpp
totalCount == 4 && oneOpen == true && bothOpen == false
```

```
# ● ● ● ● ○
```

只有一口气能成五，对手**必须立即应答**。虽然不如活四直接赢，但能强制对手应手，常用于连续冲四进攻（"冲四连攻"）。评分 10,000。

#### 死四（Dead Four）

```cpp
totalCount == 4 && oneOpen == false
```

```
# ● ● ● ● #
```

两端被完全封死，无任何威胁。评分 0。

#### 五连（Five）— 胜负判定

```cpp
totalCount >= 5
```

```
● ● ● ● ●
```

五子连珠，游戏结束。评分 1,000,000。

### 多点评分：`evaluatePoint`

```cpp
int evaluatePoint(int r, int c, Stone color)
{
    if (m_board[r][c] != EMPTY) return 0;  // 只评估空点

    int score = 0;
    for (int d = 0; d < 4; ++d)            // 四个方向
        score += evaluateLine(r, c, DIRS[d][0], DIRS[d][1], color);

    // 中心偏好（开局引导）
    int maxDist = qMax(qAbs(r - 7), qAbs(c - 7));
    if (maxDist <= 3) score += (4 - maxDist) * 3;

    return score;
}
```

**关键设计**：

- **只评估空点**：`evaluatePoint` 的作用是"如果在这个空点落子，能形成什么棋型"，已有棋子的位置返回 0
- **四方向累加**：横 `→`、竖 `↓`、斜 `↘`、反斜 `↙`，总分 = 四个方向棋型分数之和
- **中心偏好**：开局阶段引导 AI 向棋盘中心靠拢（天元附近），每近一格 +3 分

### 组合棋型判别（禁手专用）

#### 双活三（Double Live Three）— 黑棋禁手

```cpp
bool checkDoubleLiveThree(int r, int c, Stone color) const
```

**判别逻辑**：对四个方向分别检查，统计能形成活三的方向数 ≥ 2。

```
   ○
  ● ●
 ○ ● ●○    ← 横线活三 + 斜线活三 = 双活三
  ● ●
   ○
```

```cpp
for (int d = 0; d < 4; ++d) {
    // 沿方向 d 向前向后数连续同色棋子
    // 条件：forward + backward >= 2（加上自身 >= 3）且两端都空
    if ((forward + backward >= 2) && fOpen && bOpen)
        liveThreeCount++;
}
return liveThreeCount >= 2;
```

**棋理**：双活三意味着下一步有两个方向同时形成活四，对手无法同时防守。对黑棋不公平，故判为禁手。

#### 双四（Double Four）— 黑棋禁手

```cpp
bool checkDoubleFour(int r, int c, Stone color) const
```

**判别逻辑**：统计能形成四连（含冲四、活四）的方向数 ≥ 2。

```cpp
for (int d = 0; d < 4; ++d) {
    // 条件：forward + backward >= 3（加上自身 >= 4）且至少一端空
    if ((forward + backward >= 3) && (fOpen || bOpen))
        fourCount++;
}
return fourCount >= 2;
```

**棋理**：双四意味着两个方向同时冲四/活四，对手只能堵一个，**必胜**。黑棋禁止。

#### 长连（Overline）— 黑棋禁手

```cpp
bool checkLongConnect(int r, int c, Stone color) const
```

**判别逻辑**：任何方向连续同色棋子数 > 5。

```cpp
// 向前后各数最多 5 步
if (count > 5) return true;  // 六连及以上
```

**棋理**：黑棋必须恰好五连才赢，六连及以上反判负。白棋无此限制。

### 连珠形态的即时胜负判断

代码中在 **三个位置** 独立检测五连，确保不遗漏：

```
┌─────────────────────────────────────────────────────────────────┐
│                    五连检测的三个位置                               │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ① hasWinningMove() — 根节点一步杀检测                           │
│     ├─ 遍历所有空点，临时落子后检查四方向                          │
│     ├─ 任一方向 cnt >= 5 → 返回 true                             │
│     └─ 用途：AI 自己能赢直接走；对手能赢直接堵                     │
│                                                                 │
│  ② negamax() 终局快剪 — 搜索树内部                               │
│     ├─ 每步落子后检查最后落子点的四方向                            │
│     ├─ consecutive >= 5 → 返回 ±(1000000 - depth惩罚)            │
│     └─ 用途：剪枝 + 评估，越早赢/越晚输分数越高                    │
│                                                                 │
│  ③ countConsecutive() — 普通模式辅助                             │
│     ├─ wouldFormFour() 调用，判断落子后是否形成四连以上             │
│     └─ 用途：普通模式紧急点检测                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**四连 vs 五连的区别**：

| 形态 | 是否即时胜负 | 说明 |
|------|-------------|------|
| 四连（活四） | ❌ 不是 | 下一步必赢，但对手还有一次堵的机会 |
| 四连（冲四） | ❌ 不是 | 只有一口气，对手必须堵 |
| 四连（死四） | ❌ 不是 | 已无威胁 |
| **五连** | ✅ **即时胜负** | 游戏结束，无可争议 |

## 三、算法优化手段

### 1. 候选点限制

```cpp
// 只考虑已有棋子周围 2~3 格范围内的空点
int searchRange = (m_moveHistory.size() < 10) ? 2 : 3;
```

开局棋子少时范围小（2 格），中局扩大（3 格），大幅减少无效候选。

### 2. 走法排序（Move Ordering）

```cpp
std::sort(scored.begin(), scored.end(),
    [](const MoveScore& a, const MoveScore& b) {
        return a.score > b.score;  // 高分走法优先搜索
    });
```

好的走法排在前面，Alpha-Beta 剪枝效率指数级提升。

### 3. 历史启发（History Heuristic）

```cpp
// 搜索中产生 Beta 剪枝或更新 Alpha 的走法加分
m_historyTable[r][c] += depth * depth;
```

后续搜索中，曾经产生好结果的点会被优先尝试。`depth²` 确保深层搜索的好走法权重更高。

### 4. 布尔数组替代哈希集合

```cpp
bool visited[BOARD_SIZE][BOARD_SIZE] = {false};  // O(1) 查重，栈上分配
```

替代 `QSet<qint64>`，消除哈希计算和动态内存分配开销。

### 5. 评估分数缓存

```cpp
// 每个候选点只调用一次 evaluatePoint，存入 MoveScore 后再排序
for (const QPoint& pt : candidates) {
    int s = evaluatePoint(pt, color) + evaluatePoint(pt, opponent) * 0.9 + ...;
    scored.append({pt, s});
}
```

避免在 `std::sort` 的比较函数中重复调用 `evaluatePoint`（排序比较 O(n log n) 次，每次调两次评估 = 灾难）。

### 6. 动态搜索深度

```cpp
int getDynamicDepth() const {
    int moves = m_moveHistory.size();
    if (moves < 6)  return 2;   // 开局：分支多，浅搜
    if (moves < 20) return 3;   // 中局：平衡
    if (moves < 40) return 4;   // 中后局：加深
    return 5;                   // 终局： deepest
}
```

开局候选点多，深搜太慢；终局候选点少，可以搜更深。动态适配保证响应速度。

### 7. 叶子评估局部化

```cpp

## 四、数据流全链路

```
玩家点击落子
     │
     ▼
setBoardState(board, history, aiColor, playerColor)
     │
     ▼
findBestMove()
     │
     ├─【一步杀】hasWinningMove(aiColor) → 能赢？直接返回
     ├─【一步杀】hasWinningMove(enemyColor) → 对手能赢？直接堵
     │
     ├─ NORMAL 模式 ─────────────────────────────┐
     │   getAllCandidateMoves()                    │
     │   for each point:                           │
     │     attack = evaluatePoint(pt, aiColor)     │
     │     defend = evaluatePoint(pt, enemyColor)  │
     │     total = attack*12 + defend*10           │
     │   返回最高分点（随机选同分点）                │
     │                                            │
     ├─ HARD 模式 ────────────────────────────────┤
     │   generateOrderedMoves(aiColor)             │
     │   for each move (top 12):                   │

     │              │                              │
     │              ├─ 一步杀？返回极值              │

     │              ├─ generateOrderedMoves()      │
     │              └─ for each: 递归 + 剪枝       │

     │                                            │

## 五、设计亮点与不足

### ✅ 亮点

| 设计 | 优势 |
|------|------|
| Negamax 统一视角 | 代码简洁，递归取负即可切换攻防，不易出符号 bug |
| 多层攻防平衡 | 不同层级用不同权重策略，既有引导又不失灵活 |
| 一步杀检测 | O(n²) 扫描解决"眼前杀招"，避免搜索浪费 |
| 历史启发 | 越搜越准，后续迭代几乎零成本 |
| 禁手前置过滤 | 不在搜索树中浪费时间评估非法点 |
| 动态深度 | 自适应局面复杂度，保证响应速度 |

### ⚠️ 不足与可改进方向

| 不足 | 改进方向 |
|------|----------|
| 评估函数偏简单（只看连子数和开口） | 引入 VC（Victory of Continuous）搜索，专门找杀型 |
| 无置换表（Transposition Table） | 加 Zobrist 哈希缓存已搜索局面 |
| 禁手检测频繁临时落子 | 改增量维护，每次落子只更新受影响方向 |
| 无时间控制 | 加迭代加深 + 硬性超时（如 3 秒），到时返回当前最佳 |
| 棋型评分未考虑间隔（跳活三） | 增加对 `○●○●○` 跳活三的识别 |

## 六、总结

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│  「算法层面」                                                      │
│                                                                  │
│  普通模式 = 静态权重硬编码（12:10），快但"短视"                    │
│  困难模式 = 搜索树 + 轻量引导（1:0.9 / 1:1.1），慢但"深谋远虑"     │
│                                                                  │
│  核心公式：                                                        │
│    攻防平衡 = f(静态权重, 搜索深度, 走法排序, 历史启发)             │
│                                                                  │
│  ──────────────────────────────────────────────────────────────  │
│                                                                  │
│  「棋型层面」                                                      │
│                                                                  │
│  一切决策的基石 = evaluateLine() 的四方向扫描                      │
│                                                                  │
│  棋型价值阶梯：                                                    │
│    五连(100万) >> 活四(10万) > 冲四(1万) > 活三(5千)             │
│    > 眠三(500) > 活二(200) > 眠二(50)                            │
│                                                                  │
│  关键阈值：                                                        │
│    ≥500 分 → 有威胁（活三及以上），进入优先搜索                    │
│    ≥10万  → 必胜型（活四），一步杀检测直接命中                     │
│    =100万 → 五连，即时胜负                                        │
│                                                                  │
│  ──────────────────────────────────────────────────────────────  │
│                                                                  │
│  「一句话总结」                                                    │
│                                                                  │
│  五子棋 AI 的本质 = 在正确的时机，找到能形成最高价值棋型的空点      │
│                    + 阻止对手做同样的事                             │
│                                                                  │
│  普通模式用"权重"近似这个目标，困难模式用"搜索"逼近这个目标。       │
│  棋型评分体系是两种模式共享的"语言"——                              │
│  它把棋盘上的黑白排列翻译成数字，让机器能"理解"威胁。               │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```
